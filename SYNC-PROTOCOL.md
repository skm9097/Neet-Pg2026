# Sync Protocol v2 — Android ⇄ Repo ⇄ Desktop

The contract between the **neet-study-suite** Android app (pushes mistakes) and
the **neetpg-desktop** Windows app (pulls mistakes, shows flashcards, pushes
SR progress + LLM enrichment back). Both sides talk only to the GitHub
Contents/Trees REST API on `main` — no git client needed on either device.

```
┌─────────────┐   push mistake .md     ┌──────────────┐   pull + parse     ┌──────────────┐
│  Android    │ ─────────────────────► │  GitHub repo │ ─────────────────► │  Desktop     │
│  (quiz/mock)│   push session .json   │  (main)      │                    │  (flashcards)│
│             │                        │              │ ◄───────────────── │              │
└─────────────┘                        └──────────────┘   enrich write-back└──────────────┘
                                                          + sr-state push/merge
```

## Repo layout

| Path | Writer | Reader | Format |
|---|---|---|---|
| `mistakes/{subject}/{questionId}.md` | Android (merged update-in-place), Desktop (enrichment write-back) | Desktop | YAML frontmatter + Markdown (below) |
| `sessions/{YYYY-MM-DD}_{sessionId}.json` | Android | Desktop | JSON session log |
| `progress/sr-state.json` | Desktop | Desktop (pull-merged every sync) | SM-2 state, per-card `updatedAt` |
| `progress/topic-scores.json` | Desktop | (dashboards / future) | subject → unresolved ratio |
| `card-images/{cardId}.png` | Desktop | Desktop (any install) | AI-generated card visual |
| `card-images/manifest.json` | Desktop | Desktop | image details (below) |

## Mistake files: ONE file per question

`mistakes/{subject}/{questionId}.md` — **no date in the filename.**
A repeat mistake updates the existing file instead of creating a sibling:

- `times_wrong` += 1, `last_wrong` = now, `first_wrong` preserved
- one new row appended to the `## Attempts` table (rows renumbered 1..n)
- existing LLM enrichment (Key Fact / Why Wrong / tags / error_type) is
  **preserved** unless the pusher has a fresh enrichment of its own
- `is_resolved` resets to `false` (you just got it wrong again)

> v1 wrote `{YYYY-MM-DD}_{questionId}.md`, so a question wrong on two days
> produced two files with the same frontmatter `id` — the desktop then kept
> whichever parsed last and the counters reset. The desktop still *reads*
> legacy date-prefixed files, but nothing writes them anymore.

### File format

```markdown
---
id: Q0247
subject: pharmacology
topic: pharmacology
source_file: question-bank/subject-wise/pharmacology.md
tags: [cholinergic, muscarinic]
error_type: conceptual          # conceptual | recall | silly | (empty)
first_wrong: 2026-06-05T14:30:00.000Z
last_wrong: 2026-06-10T09:12:00.000Z
times_wrong: 2
times_correct: 0
is_resolved: false
---

# Q0247

## Question
…stem…

## Options
- A) Atropine
- B) Pilocarpine ✅          # ✅ marks the correct option
- C) Physostigmine
- D) Neostigmine

## Your Answer
A) Atropine

## Correct Answer
B) Pilocarpine

## Key Fact (generated by LLM)
…2–3 sentences, or the placeholder below…

## Why You Got It Wrong (generated by LLM)
_Not yet analyzed — will be filled on first desktop sync._

## Attempts
| # | Date | Answer | Result | Time | Context |
|---|---|---|---|---|---|
| 1 | 2026-06-05 14:30 | A) Atropine | ❌ | - | sess-123 |
| 2 | 2026-06-10 09:12 | A) Atropine | ❌ | - | sess-456 |
```

The desktop parser **requires** `## Question` and ≥2 `## Options` entries;
files failing that are reported in Settings → Question bank (never silently
dropped). The exact placeholder string `Not yet analyzed` is treated as
*empty* by the desktop so its Groq enrichment fills it and **writes the
enriched file back** to this same path — that's how the placeholder's promise
is kept and how enrichments reach every device.

## SR state: per-card newest-wins merge

`progress/sr-state.json`:

```json
{
  "lastUpdated": "2026-06-10T18:00:00.000Z",
  "cards": {
    "Q0247": {
      "easinessFactor": 2.36, "intervalDays": 6, "repetitions": 2,
      "nextReview": "2026-06-16", "lastGrade": 4, "status": "review",
      "updatedAt": "2026-06-10T17:59:58.000Z"
    }
  }
}
```

Every desktop sync **pulls this file first** and merges per card: the entry
with the newer `updatedAt` wins (fallback for legacy entries without
timestamps: more `repetitions` wins). Then local state is pushed back. This
makes review progress survive reinstalls and keeps multiple devices
consistent without a server.

## Card images: generate once, fetch forever

The desktop generates one visual per card (default provider: **Cloudflare
Workers AI**, model `@cf/black-forest-labs/flux-1-schnell`, user's own account
ID + API token) and pushes it to `card-images/{cardId}.png` together with a
manifest entry:

```json
{
  "Q0247": {
    "key": "md5-of-card-content-and-prompt-version",
    "file": "Q0247.png",
    "subject": "pharmacology",
    "topic": "pharmacology",
    "model": "@cf/black-forest-labs/flux-1-schnell",
    "prompt": "Medical educational infographic illustration of …",
    "at": "2026-06-10T12:00:00.000Z",
    "bytes": 184223
  }
}
```

Before calling the provider, the desktop checks (1) its local disk cache, then
(2) the repo manifest — if the manifest `key` matches the card's current
content hash, the PNG is downloaded instead of regenerated. The `key` changes
when the card's content changes, which naturally invalidates stale images.

**Budget:** at most `imagesPerDay` provider calls per local day (default 20),
persisted in `quota.json` so restarts don't reset it. A provider rate-limit
(HTTP 429 or a quota error message) blocks all generation until the next local
midnight; everything resumes automatically. Per-card failures are recorded and
shown in the desktop's **Card Images** screen, which also offers per-card
regeneration and a "generate now" batch up to the remaining budget.

## Conflict & failure handling (both sides)

- **Writes:** GET current sha → PUT with sha; on `409`/`422` sha conflict,
  re-GET once and retry (Android re-merges file content on the retry, so the
  other writer's attempt rows aren't lost).
- **Reads (desktop):** 429 / rate-limited 403 / 5xx retried with 1s→3s→9s
  backoff; truncated tree listings fail loudly instead of silently skipping
  files; a failed sync never touches the local cache — flashcards keep
  working offline from `cache.json`.
- **Android offline queue:** any failed mistake push (single *or* mock-test
  batch) is queued in SharedPreferences (max 500) and drained by Settings →
  "Sync N pending".
- **Desktop cache corruption:** a corrupt `cache.json` is backed up to
  `cache.json.corrupt.bak` before resetting, so SR progress is recoverable.

## Versions implementing v2

- Android **neet-study-suite ≥ 1.6.0**
- Desktop **neetpg-desktop ≥ 1.4.0** (card-image store: ≥ 1.5.0)
